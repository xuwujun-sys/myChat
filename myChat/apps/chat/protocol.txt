ChatRoom 第一阶段协议

1. 传输格式
   使用 TCP 传输文本，客户端和服务器都以换行符 \n 结束一条消息。
   约定文本使用 UTF-8；长度限制按字节计算，不包含行尾的 \n。
   不支持 \r\n；不发送换行符或其他 ASCII 控制字符作为消息内容。

2. 客户端命令
   REGISTER 用户名 密码\n  注册账号，注册成功后仍需登录。
   LOGIN 用户名 密码\n     验证账号，必须在发送消息前完成。
   MSG 消息内容\n     发送一条群聊消息。

   昵称为 1～32 字节，不含 ASCII 空格或控制字符；按字节比较是否重复。
   密码为 1～128 字节，不含 ASCII 空格或控制字符。
   消息内容为 1～1024 字节，可以包含空格，但不能包含 ASCII 控制字符。
   命令区分大小写；命令和参数之间用一个空格分隔。
   接收端当前按字节校验长度与 ASCII 控制字符，不校验 UTF-8 编码是否合法。
   当前密码明文存储并通过未加密 TCP 传输，仅供临时联调。

3. 服务器响应（由 ChatHandler 实现）
   OK REGISTER\n                 注册成功。
   OK LOGIN\n                    登录成功。
   USERS 昵称1 昵称2...\n       当前在线用户名单，顺序不固定。
   CHAT 昵称 消息内容\n          其他在线用户发来的群聊消息。
   ERROR INVALID_COMMAND\n       命令格式或内容不合法。
   ERROR LOGIN_REQUIRED\n         尚未设置昵称就发送消息。
   ERROR NICKNAME_TAKEN\n         昵称已被使用。
   ERROR INVALID_CREDENTIALS\n   账号或密码错误。
   ERROR DATABASE_ERROR\n        数据库操作失败。
   ERROR ALREADY_LOGGED_IN\n      已设置昵称后再次设置。
   ERROR MESSAGE_TOO_LONG\n       客户端命令行超过 1028 字节；发送错误后关闭连接。

   群聊只转发给其他已设置昵称的在线用户，不回发给发送者。

4. 分段与多条消息
   每个连接分别缓存未结束的一行；收到 \n 后提取完整行，再解析命令。
   一次接收可以包含半条、一条或多条消息。
   客户端命令行超过 1028 字节（不含 \n）时，停止处理并关闭连接；
   同一次接收中提取的行在发生超限时由调用方丢弃。
   服务器的 CHAT 响应包含昵称，最长为 1062 字节（不含 \n）。
   USERS 响应长度随在线人数增加，客户端需支持接收更长的名单；
   ChatProtocol::append 只用于接收客户端命令。

此文件描述第一阶段协议。在线用户、错误响应和转发由 ChatHandler 实现。
